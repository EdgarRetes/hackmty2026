# AGENTS.md

## What this is

factorai is a factoring marketplace for Mexican SMEs. An empresa (SME)
submits a pending invoice (factura) it's owed by a customer; multiple
financiadoras (lenders) compete by placing bids to buy that receivable at
a discount, giving the SME cash now instead of waiting for the invoice's
due date. The mercado app is the bidding/auction mechanism that matches
facturas to the winning financiadora. Right now this repo is a bare
skeleton proving the stack runs end-to-end — no real models, auth, or
matching logic exist yet.

## Monorepo layout

```
/backend    Django + DRF, API-only, deploys to Vultr via Docker
/frontend   Next.js (App Router), deploys to Vercel
```

### Backend apps (`backend/`)

- `empresas` — the SMEs requesting financing (profile, tax ID, KYB)
- `financiadoras` — the lenders placing bids (profile, funding capacity)
- `facturas` — the receivables/invoices put up for financing
- `mercado` — bids placed by financiadoras and the resulting auction
  outcomes (who won, at what price)
- `core` — shared utilities with no natural home in a domain app; also
  owns the `/api/health/` endpoint

See [`backend/AGENTS.md`](backend/AGENTS.md) for Django-specific
conventions, and [`frontend/AGENTS.md`](frontend/AGENTS.md) (generated by
`create-next-app`/`next dev`, auto-refreshed — don't hand-edit its
content) for Next.js-specific notes.

## Where to add things

- **New API endpoint**: add a view to the owning app's `views.py`, wire
  it in that app's `urls.py`, include that app's urls from
  `backend/factorai_config/urls.py` under `/api/<app>/`. Follow the
  `core` app's `health` endpoint as the reference pattern.
- **New model**: replace the placeholder comment in the owning app's
  `models.py`, then `python manage.py makemigrations`.
- **New frontend page**: add a route under `frontend/src/app/`.
- **Shared frontend types / API calls**: `frontend/src/lib/` (see
  `api.ts` for the existing pattern — typed fetch wrappers reading
  `NEXT_PUBLIC_API_URL`).
- Nothing is shared between backend and frontend today (no shared types
  package) — the API's JSON shape is the only contract between them.

## Environment variables

**Backend** (`backend/.env.example`):

| Var | Notes |
|---|---|
| `DATABASE_URL` | Postgres connection string. **Tiger Cloud's connection string omits the password** — see below. |
| `DB_PASSWORD` | The real database password. When set, overrides/fills the password missing from `DATABASE_URL`. Required for Tiger Cloud; leave unset for local SQLite/Docker Postgres with an inline password. |
| `SECRET_KEY` | Django secret key |
| `DEBUG` | `True`/`False` |
| `ALLOWED_HOSTS` | Comma-separated |
| `CORS_ALLOWED_ORIGINS` | Comma-separated, must include the frontend's origin |
| `GEMINI_API_KEY` | Reserved for later; unused so far |

**Frontend** (`frontend/.env.local.example`):

| Var | Notes |
|---|---|
| `NEXT_PUBLIC_API_URL` | Base URL of the Django backend, e.g. `http://localhost:8000` |

**The Tiger Cloud gotcha, in full**: Tiger Cloud gives you a connection
string with the password omitted. If you drop that string straight into
`DATABASE_URL` and stop there, auth will fail against Postgres even
though the URL looks valid. Always set the real password via the
separate `DB_PASSWORD` var — both `dev.py` and `production.py` parse
`DATABASE_URL` then patch in `DB_PASSWORD` over the parsed result.

## Running locally end-to-end

```bash
# backend
cd backend
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py runserver        # http://localhost:8000

# frontend (separate terminal)
cd frontend
cp .env.local.example .env.local
npm install
npm run dev                       # http://localhost:3000
```

**Verify the full loop**: open http://localhost:3000. It calls
`GET http://localhost:8000/api/health/` and renders the JSON response
(`{"status": "ok", "service": "factorai-backend"}`) on screen. If you
see that JSON rendered, backend and frontend are correctly wired.

## Conventions

- **Settings split**: backend settings live in
  `factorai_config/settings/{base,dev,production}.py`. Environment-
  specific values (secrets, hosts, DB config) never go in `base.py`.
- **API-only backend, always**: no Django templates, no admin site, no
  static file serving. Every response is JSON via DRF. UI lives entirely
  in the Next.js app.
- **All config via env vars**: no hardcoded secrets, hosts, or connection
  strings, on either side. New vars get added to the relevant
  `.env*.example` file and documented here or in the app-specific README.
- **Tailwind v4, CSS-first**: no `tailwind.config.js` — theme tokens live
  in `frontend/src/app/globals.css` via `@theme`.

## Non-goals right now

- No authentication or authorization anywhere.
- No real business logic: no bidding algorithm, no invoice scoring, no
  matching engine, no Gemini integration. Models are placeholder
  comments only.
- No production deployment configuration beyond a working Dockerfile
  (Vultr) — no CI/CD, no Vercel project settings, no secrets management.
